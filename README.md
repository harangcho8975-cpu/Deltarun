# delta run

가로 스크롤 오토 러너. 점프·슬라이드 두 버튼으로 장애물을 피하며 젤리를 모으고 결승점까지 달린다.
스테이지마다 맵이 고정되어 있어 같은 입력이면 언제나 같은 결과가 나온다. 휴대폰과 PC가 같은 화면(1280×720, 16:9)을 본다.

## 실행

```bash
npm install
npm run dev        # 개발 서버
npm run build      # 타입 검사 + dist/ 빌드
npm test           # 시뮬레이션·변환기·저장·리플레이·봇 테스트 (vitest)
npm run e2e        # 브라우저 스모크 + 화면 크기 4종 비교 (Playwright)
npm run maps       # maps/*.tmj → src/data/stages/*.json
npm run replays    # 봇으로 스테이지별 클리어 리플레이 재녹화
```

## 로비 · 준비 화면
- 로비(쿠키런 오븐브레이크 느낌): 위쪽 프로필·설정·코인, 왼쪽 이벤트·계정, 아래쪽 캐릭터·장비·뽑기, 오른쪽 아래 [플레이].
- [플레이] → 스테이지 카드 → **준비 화면**: 여기서 캐릭터(`캐릭터 변경`)와 장비 3칸을 고르고 [게임 시작]. 로비에서 여는 캐릭터·장비 화면은 구경만 합니다.
- 키보드: 로비 Enter(플레이) → 숫자(스테이지) → 준비 화면 Enter(시작), C(캐릭터), E(장비), Esc(뒤로).
- 공통 UI 부품(입체 버튼, 위쪽 바, 코인 알약, 패널, 아이콘)은 `src/ui/style.ts`.

## 장비·뽑기
- 로비 왼쪽 아래 `장비`(E), `뽑기`(G). 장비는 최대 3개까지 동시에 장착되고, 효과는 시뮬레이션에 들어가 리플레이에도 기록됩니다.
- 뽑기: 1회 30 / 10회 270 코인(10회는 레어 이상 1개 보장), 중복은 코인으로 환급. 시작 코인 100, 클리어 보너스 +50.
- 숫자는 `src/config/economy.ts`, 장비 목록은 `src/data/equipment.ts` (이름·효과는 임시).
- 테스트용: `?debug=1&coins=500` (코인 지정), `?equip=armor,bottle,sneakers` (장비 강제 장착).

## 캐릭터 뽑기·이벤트
- 처음에는 오렌지·프리스크만 있고, 나머지는 `뽑기 → 캐릭터 뽑기`에서 얻습니다 (1회 100 / 10회 900 코인, 중복은 코인 환급). 못 얻은 캐릭터는 목록에서 실루엣으로 보이고 선택할 수 없습니다.
- 로비의 `이벤트`(V): 왼쪽에 이벤트 제목이 세로로 늘어서고, 누르면 오른쪽에 그 이벤트 화면(출석 보상 +100 코인, 카오스 킹 픽업 뽑기, 신규 캐릭터 제빌). 새 이벤트는 `src/scenes/EventScene.ts`의 `EVENTS`에 추가. 숫자는 `src/config/economy.ts`.

## 제빌
- 소능력(깜짝 상자): 시작할 때와 대능력이 끝날 때마다 상자 스택 +2. 공중에서 슬라이드를 누르면 스택 1개로 상자가 왼쪽 위에서 날아와 터지고, 조각이 장애물을 부숩니다.
- 상자 스택은 최대 2개. 대능력 중(카오스 킹·제빌 모두)에는 자석처럼 젤리를 끌어당깁니다. 제빌 비행은 스크롤 1.5배, 위아래 움직임이 빠릅니다.
- 대능력(혼돈의 비행): 20초마다, 발동 중 무적·구멍 위도 바닥. 상자 폭격 3초(5개) → 돌진 2초(두 배 속도, 높이는 직접 조절) → 비행 7초(점프를 누르고 있으면 상승, 떼면 하강, 슬라이드로 낫) → 심판의 낫 3초(화면 절반에서 섬광, 화면 안 장애물 전부 파괴, 낫은 사라짐).
- 수치는 `src/config/gameConfig.ts`의 `skills.jevil`, 동작은 `src/sim/jevil.ts`.
- 테스트용: `?char=jevil&stage=stage_03&god=1&ult=2` (대능력을 2초 뒤에 시작), `?stage=stage_flat` (긴 평지).

## 클라우드 저장 (Firebase)
- 접속하면 게스트로 자동 로그인하고, 저장이 바뀔 때마다 Firestore `users/{uid}`에 올립니다. 서버·기기 중 더 최근 저장이 이깁니다. 로비 `계정`에서 상태를 봅니다.
- 설정: `src/online/firebaseConfig.ts` (공개 값). Firebase 공식 SDK(`firebase`)를 쓰고, 처음 필요할 때 내려받습니다(`src/online/firebaseBackend.ts`). 계정 화면의 `구글로 로그인`은 게스트 계정에 구글을 연결해 진행이 이어지고, 이미 저장이 있는 구글 계정이면 그 저장으로 바뀝니다.
- Firebase 콘솔에서 해둘 것: Authentication → 로그인 방법 `익명`·`Google` 켜기(승인된 도메인에 배포 주소 포함), Firestore 만들기, `firestore.rules` 내용을 규칙 탭에 붙여 넣기 (또는 `firebase deploy --only firestore:rules`).
- 실서버 점검: `npm run cloud:check` (게스트 로그인 → 읽기 → 쓰기 → 로그인 복원). 네트워크에서 Firebase 호스트가 열려 있어야 합니다.
- 끄기/테스트: `?offline=1`, 자동화 브라우저에서는 자동으로 꺼짐(`?cloud=1`로 켬).

## 전체화면

- **PC**: `F` 키, 타이틀의 "전체화면" 버튼, 일시정지 메뉴의 버튼.
- **휴대폰 (안드로이드 Chrome 등)**: 접속 후 **첫 터치** 때 전체화면 + 가로 전환을 자동으로 한다. 브라우저는 보안상 사용자가 한 번 누른 뒤에만 전체화면을 허락하므로, 접속하자마자 바뀌는 것은 불가능하다. 전체화면 중 **뒤로가기**를 누르면 페이지를 떠나지 않고 전체화면과 가로 고정만 풀린다 (처음부터 가로였다면 가로 고정은 건드리지 않는다).
- **iPhone Safari**: 일반 웹페이지의 전체화면을 지원하지 않는다. 공유 버튼 → "홈 화면에 추가"로 설치한 아이콘으로 열면 주소창 없이 전체화면(`manifest.webmanifest`, `apple-mobile-web-app-capable`)이 된다. 안드로이드도 같은 방법으로 설치하면 처음부터 전체화면으로 열린다.

## 이미지·사운드 교체

모든 에셋은 `public/assets/manifest.json`의 키로만 쓰인다. `path`가 `null`이면 색 사각형 플레이스홀더가 자동으로 생기고, 사운드는 무음이 된다.

1. 파일을 `public/assets/images/`(또는 `audio/`)에 넣는다. 스프라이트 시트는 프레임을 가로 한 줄로.
2. `manifest.json`에서 해당 키의 `path`를 `"images/player_run.png"`처럼 바꾸고, `width`·`height`(프레임 1개 크기)·`frames`를 맞춘다.
3. 코드는 고치지 않는다. 히트박스는 `src/config/gameConfig.ts` 값이라 이미지가 바뀌어도 난이도는 그대로다.

## 맵 · 스테이지 만들기
- 카카오 쿠키런처럼 **맵 하나 안에 스테이지 10개**가 이어져 있습니다(맵 "시작", 약 6분). 일정 거리를 가면 "STAGE n" 배너와 함께 다음 스테이지로 들어가고, 배경 색감이 바뀌며, 스테이지가 바뀌는 곳마다 회복 물약 2개가 있습니다.
- 배치는 `scripts/stages/episode1.ts`(스테이지별 `low()`·`high()`·`air()`·`hole()`·`item()`·`bear()`·`smash()`, 점프 정점에 `'card'`·`'rune'`·`'big'`), 이어 붙이기는 `scripts/build-stages.ts`.
- `npm run stages`: 실제 물리로 가장 넉넉한 점프·2단 점프·슬라이드 시점을 찾고, 그 궤적(몸 중심)을 따라 44px 간격으로 젤리를 깝니다. 정답 조작으로 피격 0·젤리 100%인지 검증한 뒤 `maps/ep1.tmj`·데이터·정답 리플레이를 씁니다.
- 2단 점프 젤리 길은 좌우 대칭 아치(생성기가 대칭 포물선에 가장 가까운 2단 시점을 고르고, 몸에 닿는 범위 안에서 포물선 위에 깐다). `magnetField(len)`: 자석 + 길 위쪽 젤리 3줄(자석 없이는 다 못 먹음).
- 젤리 점수: 일반 10, 곰 100, 카드 300, 델타룬 문양 3000.

## 디버그 (`?debug=1`)

- 히트박스 표시, 정보 패널, `I` 무적, `1`~`4` 배속(×1/×2/×4/×0.25), `R` 리플레이 저장, 오른쪽 위 수치 조절 패널
- `?debug=1&stage=stage_02&x=9000`: 스테이지 2의 x=9000에서 바로 시작 (`stage_test`는 수기 테스트 맵)

## 구조

- `src/sim/` — 게임 규칙. Phaser를 쓰지 않는 순수 TypeScript, 1틱 = 1/60초 고정. `step(state, input)`이 상태를 전진시키고 이벤트를 돌려준다.
- `src/scenes/`, `src/render/`, `src/input/` — Phaser 화면·입력. 시뮬레이션 상태를 읽기만 한다.
- `src/data/stages/` — 변환기가 만든 스테이지 JSON (직접 고치지 않음)
- `scripts/` — Tiled 변환기, 리플레이 녹화
- `tests/`, `e2e/` — 테스트
